IzPack is a widely used open-source installer framework that creates Java-based installation packages. A critical path traversal vulnerability exists within the `UnpackerBase.unpack()` method (CVE-2026-54550), which resolves pack-file target paths without canonicalization or directory containment checks. Because IzPack installers lack digital signature requirements, an attacker can modify a legitimate installer JAR to include pack entries containing `../` traversal sequences. When a victim executes the modified installer, the application blindly writes malicious files to locations outside the intended installation directory, using the victim's privileges. This impact is exacerbated when installers are run with administrative privileges on Windows, enabling the placement of malicious binaries into system directories or startup folders to achieve persistent code execution. The vulnerability remains unpatched in the latest versions of the IzPack framework.

## Attack Chain

1. Attacker identifies a software product that utilizes the IzPack framework for its distribution installer.
2. Attacker downloads the legitimate installer JAR and uses standard archival tools to extract its contents.
3. Attacker modifies the installer's pack configuration, adding entries with `../` traversal patterns in the `targetPath` attribute.
4. Attacker inserts a malicious payload (e.g., a backdoor executable) into the JAR package and references it with the traversed path.
5. Attacker distributes the trojanized installer through social engineering, deceptive websites, or supply chain compromise.
6. Victim executes the installer, often providing local administrator credentials as requested by the installation wizard.
7. `UnpackerBase.unpack()` processes the malicious path, writing the payload into a sensitive location (e.g., startup folder).
8. System reboots or the victim performs an action that triggers the malicious binary, resulting in full system compromise.

## Impact

Successful exploitation allows for arbitrary file write and overwrite capabilities on the victim's system. Depending on the target path chosen by the attacker, this can lead to remote code execution, privilege escalation, and system persistence. Since IzPack installers are frequently run as privileged users during software installation, the impact is often a complete takeover of the host machine. Every user running software generated by IzPack versions 5.2.6 or earlier is potentially exposed to this supply-chain-style attack vector.

## Recommendation

- Implement file integrity monitoring (FIM) on sensitive system directories such as the Windows Startup folder and System32 to detect unexpected file writes following installer execution.
- Advise end-users to verify the authenticity and source of installer packages, prioritizing software obtained from verified vendor distribution channels over third-party repositories.
- Monitor for the execution of Java-based installer processes that are spawned by unexpected parent processes or that exhibit unusual network connectivity after starting.
- Review internally developed installers that leverage the IzPack framework for the presence of the vulnerable `UnpackerBase` component and mitigate by implementing manual path validation wrappers if code-level access is available.
- Prohibit the execution of unsigned or unverifiable installer packages in hardened production environments.
