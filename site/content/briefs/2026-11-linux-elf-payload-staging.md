## Overview

Adversaries often stage Linux payloads in writable, non-standard, or temporary directories prior to execution. This activity involves the creation or renaming of ELF-formatted files by common utilities (e.g., curl, wget, scp) or processes executing from unusual locations.

## Attack Chain

Adversaries use transfer utilities, file-manipulation utilities, scripting runtimes, or executables running from unusual locations to create ELF files in temporary, shared-memory, runtime, mail, or web directories. This behavior is a common precursor to malware execution or lateral movement.

## Impact

Staging ELF files in these directories may indicate an adversary is actively transferring or preparing a Linux payload for subsequent execution on the target system.

## Recommendation

- Deploy the provided EQL rule via Elastic Defend to monitor file creation and rename events in high-risk directories.
- Enable the advanced setting 'linux.advanced.events.populate_file_data' set to 'true' within the Elastic Defend integration policy to ensure the necessary file metadata (file.Ext.* fields) is captured; this is required for the rule to function.
- Audit existing build, deployment, and container-initialization workflows to differentiate legitimate staging behavior from potential malicious activity and establish necessary exclusions.
