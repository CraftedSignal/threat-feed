## Overview

LiteLLM is an AI gateway that centralizes API credentials for various providers like OpenAI and Anthropic. A pre-authentication SQL injection vulnerability, identified as CVE-2026-42208, allows an unauthenticated remote attacker to extract all stored API keys and provider credentials. Successful exploitation is equivalent to compromising all connected AI provider accounts. Open-source intelligence suggests active exploitation attempts in the wild. The vulnerability stems from directly concatenating the Bearer token value from incoming HTTP requests into a SQL query without proper sanitization before authentication. This allows for arbitrary SQL injection. The issue is resolved in LiteLLM version v1.83.7. Defenders should prioritize patching or mitigating this vulnerability immediately due to the high risk of credential compromise.

## Attack Chain

1.  The attacker sends a malicious HTTP request to the LiteLLM server.
2.  The HTTP request contains a crafted `Authorization: Bearer` header.
3.  The `Bearer` token value contains a SQL injection payload.
4.  LiteLLM's authentication mechanism directly concatenates the `Bearer` token into a SQL query without sanitization.
5.  The injected SQL code executes within the LiteLLM database.
6.  The injected SQL is designed to extract API keys and provider credentials stored in the database.
7.  The extracted credentials are returned to the attacker within the HTTP response, or via an out-of-band channel configured in the injected SQL.
8.  The attacker uses the stolen API keys and credentials to access and control the victim's AI provider accounts.

## Impact

Successful exploitation of this vulnerability allows an attacker to steal all API keys and credentials managed by the LiteLLM instance. This is equivalent to losing control over all connected AI provider accounts, including those for OpenAI and Anthropic. This may lead to unauthorized usage of AI services, data breaches, and other malicious activities. Open-source reporting indicates active exploitation, suggesting a high risk of widespread impact.

## Recommendation

*   Immediately patch LiteLLM instances to version v1.83.7 to remediate CVE-2026-42208.
*   If patching is not immediately feasible, configure `"set disable_error_logs: true"` under general settings in LiteLLM to mitigate the vulnerability, as recommended by CCB.
*   Deploy the Sigma rule `Detect Suspicious LiteLLM Authentication Header` to identify potential exploitation attempts by monitoring for suspicious patterns in the `Authorization` header of HTTP requests to the LiteLLM server.
*   Upscale monitoring and detection capabilities, as recommended by CCB, to identify any related suspicious activity and ensure a swift response in case of an intrusion.
