The Windows Startup folder is a special directory where programs placed within it are automatically executed during account logon, offering adversaries a convenient method for achieving persistence. This rule focuses on detecting unsigned processes that create or modify files within these Startup folder locations. The rule specifically looks for processes that lack valid code signatures attempting to establish persistence. The rule aims to detect this activity to identify potential persistence mechanisms employed by attackers. This activity could be indicative of malicious software attempting to establish persistence on a compromised system.

## Attack Chain

1. A user executes a malicious program (e.g., via phishing or drive-by download).
2. The malicious program checks the integrity and code signature of its own executable, discovering that it is not trusted or signed.
3. The malicious process attempts to copy itself or a component to a common writable directory like `C:\Users\*.exe`, `C:\ProgramData\*.exe`, `C:\Windows\Temp\*.exe`, `C:\Windows\Tasks\*.exe`, `C:\Intel\*.exe`, or `C:\PerfLogs\*.exe`.
4. The malicious process writes a shortcut (.lnk) or executable file into the Startup folder (`C:\Users\*\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\*` or `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp\*`).
5. The system is restarted or the user logs off and logs back on.
6. The shortcut or executable in the Startup folder executes the malicious process when the user logs on.
7. The malicious process now runs with the user's privileges, maintaining persistence.

## Impact

A successful attack leveraging startup folder persistence can lead to the persistent presence of malware on a system, allowing attackers to maintain unauthorized access. This can lead to data theft, system compromise, and further propagation of the attack within the network. The impact includes potential data breaches, financial losses, and reputational damage. The severity depends on the privileges of the user account and the capabilities of the malware.

## Recommendation

*   Enable process creation and file modification logging to capture the activity described in this brief.
*   Deploy the provided Sigma rule `Detect Unsigned Process Writing to Startup Folder` to identify potentially malicious persistence mechanisms.
*   Investigate any alerts generated by the Sigma rule by examining the parent process and the legitimacy of the unsigned executable.
*   Implement a policy to restrict unsigned executables from running in the environment, if feasible, to mitigate the risk of this persistence technique.
*   Monitor file modifications in the startup folder using file integrity monitoring (FIM) tools.
*   Regularly scan systems for suspicious files and processes, especially in the startup folders.
