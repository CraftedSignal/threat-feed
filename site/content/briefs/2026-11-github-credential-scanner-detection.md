## Overview
GitHub audit activity has been identified originating from user agents associated with credential-scanning and secret-harvesting tools such as TruffleHog or Nord Stream. These tools systematically traverse repository contents and API routes to locate hardcoded secrets, tokens, deploy keys, and other credentials.

## Attack Chain
Tools identify themselves in the github.user_agent string when interacting with the GitHub API. The activity typically presents as a burst of API requests targeting secrets, contents, and repository routes. This behavior is used to mine an organization for exposed credentials, serving as a precursor to credential access and data collection from code repositories.

## Impact
The use of these tools by an adversary or via unsanctioned scans can lead to the identification of sensitive credentials, potentially facilitating unauthorized access and data exfiltration from repositories.

## Recommendation
Security teams should review GitHub audit logs to identify these tools and distinguish between authorized CI secret-scanning jobs and unauthorized reconnaissance activity. Organizations should investigate the authenticating identity, source IP, and tokens used, and rotate any secrets or tokens determined to be exposed. Compensating controls may include rate-limiting or blocking the identified actor IP addresses.
