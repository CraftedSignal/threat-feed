The CMB2 plugin for WordPress (versions 2.13.1 and earlier) contains a security flaw resulting in unauthenticated Stored Cross-Site Scripting (XSS). The vulnerability exists because the plugin fails to properly sanitize input or escape output for the 'textarea_code' field type, including specific implementations like 'kl_code' and 'kl_post_code'. 

Defenders should note that the attack vector is particularly accessible because the CMB2 box nonce, a value usually intended for CSRF protection, is emitted to all visitors via a simple GET request. This allows unauthenticated, remote attackers to craft malicious payloads and successfully submit them to the 'textarea_code' parameter. Once injected, the malicious scripts execute in the browser session of any user viewing the compromised page, potentially leading to administrative session hijacking, unauthorized actions, or site-wide defacement.

## Impact

The vulnerability poses a high risk to WordPress sites utilizing the CMB2 plugin, particularly those exposing public-facing forms that use the affected 'textarea_code' fields. Successful exploitation allows an unauthenticated attacker to inject arbitrary JavaScript, which executes with the privileges of the victim viewing the affected content. Potential consequences include full compromise of administrative accounts, redirection to malicious domains, and exfiltration of sensitive site data.

## Recommendation

1. Immediately audit all WordPress deployments for the CMB2 plugin version 2.13.1 or lower.
2. Disable public access to forms utilizing the 'textarea_code' field until a security patch is verified and applied by the vendor.
3. Implement strict Content Security Policy (CSP) headers to mitigate the impact of unauthorized script execution.
4. Monitor web server logs for suspicious POST requests targeting endpoints that interact with CMB2 box nonces.
