This detection focuses on the use of the `Get-WMIObject Win32_Group` command executed via PowerShell or command-line interfaces to enumerate local groups on Windows endpoints. This activity is a characteristic component of the discovery phase in an attack lifecycle. Attackers perform this enumeration to identify group memberships and high-value accounts, which facilitates targeted privilege escalation or lateral movement within a compromised network. 

Defenders should note that while this activity is frequently observed in post-compromise reconnaissance, it may also be generated by administrative scripts or security auditing tools. Detection relies on endpoint telemetry, specifically process creation logs that capture full command-line arguments. By monitoring for these specific WMI queries, security operations centers can identify potential unauthorized reconnaissance before an adversary proceeds to exploit identified accounts.

## Impact

Successful execution of group discovery allows an attacker to map out local administrative groups and user access rights. This provides the necessary intelligence to identify accounts for credential harvesting, lateral movement, or escalation to higher-privileged contexts. The scope of impact is typically restricted to local endpoint access, but it serves as a critical prerequisite for achieving wider domain-level objectives.

## Recommendation

Deploy detection rules to monitor for process creation events that include both 'Get-WMIObject' and 'Win32_Group' strings within the command line.

* Deploy the provided Sigma rule to your SIEM to monitor for PowerShell and Command Prompt executions indicative of group enumeration.
* Enable Sysmon Event ID 1 or Windows Security Event ID 4688 to ensure full command-line capture for visibility into these execution patterns.
* Tune detections against established administrative baselines to minimize noise from system management tools and legitimate security auditing scripts.
